# Сборка новых классов Fore25 отдельно от JInvFore Java 8

Новые классы `ru.inversion.fore` используют Java 25 и JavaFX 25. Их нельзя
компилировать с `source`/`target`/`release` 8 или запускать на Java 8.
Отдельный POM читает эти исходники из существующего `src/main/java`, но
компилирует только `ru/inversion/fore/**`. Старые исходники JInvFore и его
корпоративный parent в эту сборку не входят.

Все команды ниже выполняются из корня репозитория. Сначала проверьте JVM Maven:

```sh
mvn -version
```

В выводе должна быть Java 25. При другой версии выберите установленный JDK 25
в `JAVA_HOME` и в настройках Maven Runner в IDE. Одной замены `release` в POM
недостаточно: сам Maven должен работать на подходящем JDK.

## Контролы и действия

Для независимой проверки `IForeControl`, `ForeTextField`, кнопок, меню,
действий и FXML используется уже существующая сборка Scene Builder:

```sh
mvn -f scenebuilder/pom.xml -Pheadless clean test
```

Профиль `headless` добавляет Monocle только в тестовую JVM; он не входит
в JAR для Scene Builder. Тесты используют настоящие классы JavaFX 25.0.4
и ControlsFX 11.2.4. Без профиля тесты используют обычную графическую среду.
Этот набор не включает `FormControllerTest` и не проверяет весь runtime.
Эта UI-сборка не зависит от `JInvCommon` и не компилирует JInvFore Java 8.
В этот набор входят проверки `ActionKeyBinder`: оба сочетания CREATE,
disabled, конфликты, смена клавиш, области разных Scene и снятие привязок.

## Все новые классы и тесты формы

Контроллер, launcher, валидация и настройки приложения используют классы
`Checks`, `TaskContext`, `IExceptionInfo` и `S` из `JInvCommon`. Отдельная
сборка подключает готовый JAR `ru.inversion:JInvCommon:1.0.0`, а не компилирует
старый JInvFore:

```sh
mvn -f standalone/pom.xml -Pheadless clean test
```

Этот запуск также проверяет настоящий запуск FXML-формы, veto закрытия,
снятие клавиш на FX-потоке и последующий `closeResources()` на виртуальном
потоке. Пример регистрации действия и описание lifecycle находятся
в [руководстве Scene Builder](../scenebuilder/README.md).

Нужен доступ к корпоративному Maven-репозиторию через ваши рабочие Maven
настройки либо уже установленный в локальном Maven-репозитории `JInvCommon`
с его зависимостями. Версию можно переопределить через
`-Djinvcommon.version=<ваша-версия>`. Если Maven сообщает о недоступном
Nexus, `maven-default-http-blocker` или отсутствующем `JInvCommon`, это
отдельная ошибка разрешения зависимостей. Сборка `scenebuilder` выше
корпоративный репозиторий не использует.

JAR, скомпилированный под Java 8, можно использовать как зависимость сборки
на JDK 25; совместимость конкретного runtime проверяется тестами. Обратное
направление не работает: Java 8 не сможет загрузить новые классы Fore25.

## Если новые исходники пока внутри старого JInvFore

Оба каталога с POM можно использовать рядом с тем же `src` в рабочей копии
JInvFore. Запускайте их через `mvn -f ...` на JDK 25.
Чтобы отдельная старая сборка JInvFore продолжала работать на Java 8,
исключите новые пакеты из её `maven-compiler-plugin`:

```xml
<configuration>
   <excludes>
      <exclude>ru/inversion/fore/**</exclude>
   </excludes>
   <testExcludes>
      <testExclude>ru/inversion/fore/**</testExclude>
   </testExcludes>
</configuration>
```

Эти исключения относятся только к старому Java 8 POM. Старые классы также
не должны ссылаться на новые классы Fore25. Для IDE задайте отдельному
Fore25 Maven-проекту JDK 25, а JInvFore оставьте на JDK 8.

## Пример TableView и редактора записи

Импортируйте `standalone/pom.xml` как Maven-проект, выберите JDK 25 и запустите
из IDE основной класс `ru.inversion.fore.demo.table.TableViewDemo`.
В параметрах JVM укажите `--enable-native-access=ALL-UNNAMED`.
Нужен настоящий `JInvCommon` из описанной выше рабочей конфигурации Maven.

В примере используется обычный JavaFX `TableView` с колонками ID и названия.
Пять стандартных действий разделяются между кнопками панели, меню и клавишами:

| Действие | Клавиши | Условие доступности |
|---|---|---|
| Создать | F2, F6 | Всегда |
| Изменить | F4 | Выбрана запись |
| Просмотр | F3 | Выбрана запись |
| Удалить | Shift+F6 | Выбрана запись |
| Обновить | F8 | Всегда |

Редактор открывается через `FormLauncher` в режиме `INSERT`, `EDIT` или `VIEW`.
Сохранение вызывает `ok()`, проверяет непустое название длиной до 120 символов
и возвращает черновик через `FormResult`. Отмена не меняет сохранённую запись.
Просмотр разрешает только чтение. После сохранения таблица восстанавливает
выбор по ID, даже когда изменение названия перемещает строку при сортировке.
После удаления выбирается соседняя строка; пустой список отключает действия
с выбранной записью. При закрытии снимаются привязки действий и сортировки.

`RecordStore` хранит демонстрационные данные в памяти: после перезапуска снова
появляются три исходные записи. Это пример подключения формы; доступа к БД нет.
При переносе в приложение загрузку и сохранение замените своим репозиторием.

Проверки создания, валидации, отмены, изменения, сортировки, просмотра и удаления
входят в тесты полной сборки:

```sh
mvn -f standalone/pom.xml -Pheadless clean test
```
