# LXML 1: декларативный LOV

`ForeLov` показывает список и выполняет фоновый поиск. `LxmlLoader` создаёт его из XML. `LovBinding` связывает выбор с полем и получателями результата. Ни один из этих классов не требует `TaskContext` или `JInvCommon`.

## Минимальное определение

```xml
<lov xmlns="urn:inversion:fore:lov:1" version="1" id="departments" title="Подразделения">
   <behavior validate-from-list="true"/>
   <columns>
      <column name="ID" type="long" width="0" return-to="departmentId"/>
      <column name="CODE" title="Код" return-to="departmentCode"/>
      <column name="NAME" title="Наименование" width="300" return-to="departmentName"/>
   </columns>
   <source><provider ref="departments"/></source>
</lov>
```

Полные запускаемые/SQL-примеры:

- [departments.lxml](../src/main/resources/ru/inversion/fore/demo/lov/departments.lxml).
- [departments-sql.lxml](../src/main/resources/ru/inversion/fore/demo/lov/departments-sql.lxml).
- [lov.xsd](../src/main/resources/ru/inversion/fore/form/lov/lov.xsd) — схема для IDE и загрузчика.

Порядок секций: `comment?`, `window?`, `behavior?`, `search?`, `columns`, `source`. Все неизвестные атрибуты и элементы запрещены. Опечатка в поведении не превращается в молча проигнорированную настройку.

## Атрибуты

| Элемент | Атрибуты и значения по умолчанию |
|---|---|
| `lov` | Обязательные `id`, `title`, `version="1"` |
| `window` | `width="640"`, `height="420"`, необязательная пара `x`, `y`; `automatic-position="false"`, `automatic-column-width="false"`, `direction="inherit"`, `style-class=""` |
| `behavior` | `auto-display="false"`, `auto-refresh="true"`, `auto-select="false"`, `auto-skip="false"`, `filter-before-display="false"`, `validate-from-list="false"`, `key="F9"` |
| `search` | `mode="prefix"`, `case-sensitive="false"`, `min-length="0"`, `max-rows="200"` |
| `column` | Обязательный `name`; `title` по умолчанию равен имени; `type="string"`, `width="160"`, необязательный `return-to` |
| `provider` | Обязательный `ref`, разрешаемый через `LovSources` |
| `sql` | Обязательный `ref`; `fetch-size="100"`, `timeout-seconds="30"`; один `query`, затем упорядоченные `bind` |
| `bind` | Обязательный `name` |
| `value` | Обязательный `column`; `null="false"` |

Режимы поиска: `prefix`, `contains`, `exact`. Направления: `inherit`, `left-to-right`, `right-to-left`. Координаты и размеры — логические пиксели JavaFX. Размер окна не меньше 240 × 180; при показе окно вписывается в экран. Лимит выдачи от 1 до 10000. Ширина 0 скрывает колонку. Поиск и проверка ввода используют первую видимую колонку; её перестановка пользователем запрещена.

Типы: `string` → `String`, `long` → `Long`, `decimal` → `BigDecimal`, `date` → `LocalDate`, `datetime` → `LocalDateTime`, `boolean` → `Boolean`. Даты записываются в ISO-формате, десятичный разделитель — точка. Переполнение или дробь при `long` — ошибка. Все колонки должны присутствовать в каждой строке, даже если их значение `null`. Пустая строка и `null` различаются.

`title="%ключ"` разрешается через `new LxmlLoader(bundle)`. `%%` в начале обозначает буквальный знак `%`. Служебные надписи самого окна инкапсулированы в `ru.inversion.fore.form.lov.lov.properties`.

## Подключение к форме

```java
var sources = new LovSources().database("main", applicationDataSource);
var lov = new LxmlLoader().load(
      getClass().getResource("departments-sql.lxml"), sources);

var binding = new LovBinding(lov, codeField, Map.of(
      "departmentId", LovBinding.Target.of(departmentIdProperty, Long.class),
      "departmentCode", LovBinding.Target.text(codeField.textProperty()),
      "departmentName", LovBinding.Target.text(nameField.textProperty())),
      () -> Map.of("companyId", companyIdProperty.get()),
      nextField::requestFocus);

chooseButton.setOnAction(event -> binding.show());
saveButton.setOnAction(event -> binding.validate().thenAccept(valid -> {
   if (valid) saveForm();
}));

// При завершении работы формы, в потоке JavaFX.
binding.close();
```

Последняя строка относится к обработчику закрытия формы, а не выполняется сразу после настройки кнопок. Один `LovBinding` владеет одним `ForeLov`; определение можно переиспользовать для создания других экземпляров. `TextField` можно заменить на существующий `ForeTextField` без изменения его класса.

Вместо рефлексии приложение явно регистрирует writable properties. Для своей конвертации используется `new LovBinding.Target<>(property, converter)`. Односторонне связанный получатель и назначение одной property нескольким возвращаемым колонкам запрещены. Для `validate-from-list=true` получатель первой видимой колонки должен быть именно `codeField.textProperty()`.

`binding.show()` / `binding.validate()` возвращают `CompletableFuture<Boolean>`. `false` означает, что выбор/проверка не завершены успешно, включая отмену. Ошибка доступна через `binding.errorProperty()`. Ошибки загрузки внутри ещё открытого окна доступны через `lov.errorProperty()`, окно позволяет повторить поиск. Подтверждение возвращает все настроенные значения. Отмена выбора не присваивает получателям ничего.

Пустое поле при явной проверке очищает всех получателей; обязательность контролирует форма. Состояния привязки: `UNCHECKED`, `VALIDATING`, `VALID`, `INVALID`. После изменения текста состояние снова `UNCHECKED`. При сохранении вызывайте `validate()` заново, даже если предыдущая проверка была успешна: параметры и данные источника могли измениться.

Асинхронная проверка не блокирует навигацию JavaFX. Кнопка сохранения должна дождаться завершения проверки и затем выполнить остальные проверки формы. Ввод нового текста во время запроса делает прежний результат неприменимым. Смена значений параметров до подтверждения также отменяет применение результата; значения параметров должны быть неизменяемыми скалярами.

`auto-skip=true` требует явного `nextFocus`. Не используется внутренний, нестабильный API обхода фокуса JavaFX. F9 можно переопределить через синтаксис `KeyCombination`, например `key="Ctrl+L"`.

## Контракт источника

```java
LovDataSource source = request -> {
   // Выполняется в рабочем потоке. Поиск и ограничение выдачи делает источник.
   return loadFromService(request.text(), request.mode(), request.parameters(), request.maxRows());
};
var sources = new LovSources().provider("departments", source);
```

`loadFromService` в этом фрагменте — прикладная функция, возвращающая `LovDataSource.Result`.

- `Request` содержит определение, текст, режим и снимок небольшого набора параметров. `matches(row)` реализует правила встроенного статического источника; `pattern()` строит JDBC LIKE-параметр.
- `Result.rows` содержит не более `maxRows` строк. `complete=true` означает, что других подходящих строк нет; `false` — что выдача ограничена. Нельзя помечать произвольно обрезанную выдачу как полную.
- Источник передаёт владение списком и больше его не меняет. `Result` оборачивает список без копирования; `TableView` использует представление над тем же списком. `LovRow` фиксирует карту значений одной строки.
- Отдельной полной копии справочника, `SortedList`, списка прошлых результатов и истории курсора нет. SQL материализует только ограниченную текущую выдачу. Статический источник рассчитан на небольшие встроенные справочники.
- Отмена прерывает рабочую задачу, а номер запроса предотвращает публикацию устаревшего ответа. При отмене невосприимчивый к прерыванию драйвер может продолжать свою работу до собственного тайм-аута.

Для источника поверх `IDataSet` нужен отдельный контракт владения и чтения. Он намеренно не реализован в этом прототипе: работа над текущим адаптером датасета приостановлена.

## SQL

Соединение выдаёт зарегистрированный `DataSource`, по одному на запрос. `close()` возвращает его в пул; общий текущий Connection формы сюда передавать не следует. Справочник видит данные в транзакционном контексте своего соединения; для доступа к незакоммиченным данным формы нужен специальный provider.

`query` — доверенный SQL приложения. XML не предназначен для загрузки SQL от конечных пользователей. Пользовательский ввод и параметры передаются исключительно через `PreparedStatement.setObject`, без подстановки в текст SQL. JDBC read-only cursor не является политикой прав доступа БД.

`<bind>` соответствует каждому `?` по порядку. Обычное имя берётся из карты параметров; отсутствие ключа — ошибка, значение `null` допустимо. Служебные имена:

| Имя | Значение |
|---|---|
| `$pattern` | Экранированный LIKE-шаблон с учётом режима поиска |
| `$text` | Исходный текст без нормализации |
| `$limit` | `maxRows + 1`, если требуется явное ограничение в SQL |

Для `$pattern` в запросе требуется `LIKE ? ESCAPE '!'`. В нечувствительном к регистру примере применяется `upper(code)`; Java использует `Locale.ROOT`. При специальных правилах Oracle NLS/колляции адаптируйте SQL/provider и проверьте правила сравнения отдельно. `%`, `_`, `!` в пользовательском вводе экранируются. Первая видимая колонка должна соответствовать SQL-условию поиска; прототип проверяет это при получении строк.

Сортировка задаётся SQL `ORDER BY` либо источником; щелчки по заголовкам не запускают локальную сортировку. `fetch-size` — только подсказка JDBC. `max-rows` ограничивает память результата; для тяжёлых запросов нужен подходящий план/индекс и, при необходимости, серверный лимит. Драйвер может буферизовать строки самостоятельно.

## Кэш, потоки и безопасность загрузки

По умолчанию `auto-refresh=true`: каждый вызов выполняет поиск заново, окно освобождает выдачу при закрытии. При `false` хранится только последний ответ для того же текста, режима и параметров. `refresh()` игнорирует кэш и повторяет текущий поиск; `invalidate()` очищает его. Глобального кэша нет.

Все операции с окном и привязкой вызываются в FX Application Thread. Определение можно прочитать заранее в другом потоке. По умолчанию запросы выполняются на виртуальных потоках Java 25; допускается передать собственный `Executor`, работающий вне JavaFX. Не вызывайте `join()`/`get()` у будущего результата на FX-потоке.

Загрузчик использует встроенную XSD, запрещает DTD, внешние сущности, XInclude и внешние схемы. Размер XML ограничен 1 МиБ. Ссылок на исполняемые классы, скриптов и автоматического разрешения имён получателей в XML нет. `read(InputStream)` не закрывает поток вызывающего кода; `read(URL)` и `load(URL, …)` закрывают открытый ими поток.

Список реализованных и отложенных соответствий Oracle Forms находится в [каталоге](lov-oracle-forms.md).
